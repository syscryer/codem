# Task: 工作流实例与实时画布

## Background

现有工作流页面将每次执行称为“运行记录”，详情采用节点列表加日志区域。这种呈现只能查看摘要，无法直观看到 DAG 在本次执行中的实时状态，也弱化了“同一工作流可以产生多次独立执行”的概念。需要将其升级为“工作流实例”：每次启动生成一个独立、可恢复、包含定义快照和节点运行态的实例。

## Objective

将运行记录升级为可持久化的工作流实例，实例详情以只读画布实时展示节点状态，并支持从右侧查看节点日志。

## Scope

In scope:

- 将工作流二级视图从“运行记录”更名为“工作流实例”。
- 每次正式或临时启动都创建独立实例，记录来源、工作流定义快照、用户目标、实例状态、节点状态、时间信息和节点日志。
- 实例列表同时展示运行中与历史实例，并提供状态、进度、启动时间和耗时等可扫描信息。
- 点击实例进入该实例启动时的只读画布，而不是现有节点列表详情。
- 画布实时展示 `pending / running / waiting / completed / failed / cancelled` 节点状态，并能体现并行分支、汇合和当前推进位置。
- 点击画布节点后，从右侧打开日志抽屉，以聊天形式展示该节点的输入、Agent 公开输出、工具调用、错误、多轮讨论和用户补充指导。
- 实例完成或中断后继续持久化，可在刷新和桌面重启后恢复当时的画布、节点状态和日志。
- 历史实例读取启动时冻结的工作流快照；后续编辑、发布更新、下线或删除工作流定义，不改变已有实例。
- 实例画布默认只读；根据实例状态提供取消运行、重试失败节点和处理人工确认等运行操作，但不允许修改节点或连线。

Out of scope:

- 不在实例画布中编辑工作流定义。
- 不让历史实例跟随最新工作流定义自动变化。
- 不在本阶段增加工作流版本回滚、审批发布、云同步或跨设备同步。
- 不将完整日志或大文本重复嵌入工作流定义；定义和实例继续保持职责分离。
- 不重做 Agent 的聊天渲染和工具事件协议，优先复用现有运行事件及聊天展示组件。

## Impact

- 产品模型：工作流定义描述“如何运行”，工作流实例描述“某一次实际运行结果”。
- 前端：工作流主页导航、实例列表、只读 React Flow 画布、节点状态样式和右侧日志抽屉。
- 运行态：实例状态由节点真实状态派生，支持串行、并行、汇合、等待、失败和取消。
- 持久化：现有 `agent_mux_workflow_runs` 文档升级为实例文档，保存定义快照与可恢复运行态；需兼容已有运行记录。
- 性能：实例画布与日志按需加载，避免列表页加载所有节点完整日志；长日志需要增量追加或虚拟化。

## Acceptance Criteria

- [ ] 页面导航显示“工作流 / 工作流实例”，不再使用“运行记录”作为一级概念。
- [ ] 每次启动生成新的实例 id，同一工作流多次启动互不覆盖。
- [ ] 实例列表可区分运行中和历史状态，并显示准确进度与时间信息。
- [ ] 点击实例进入只读画布，节点和连线位置来自该实例的定义快照。
- [ ] 运行中节点状态可实时更新；并行节点可同时显示运行中，汇合节点等待全部依赖完成。
- [ ] 点击节点打开右侧日志抽屉，切换节点时抽屉内容随之切换，关闭后不影响画布状态。
- [ ] 节点日志保留公开输入输出、工具事件、错误、多轮讨论与用户操作，不保存隐藏思维链或敏感大内容。
- [ ] 刷新或重启后，运行中和已结束实例都能从持久化恢复一致状态。
- [ ] 编辑、下线或删除工作流定义后，历史实例画布和日志保持不变。
- [ ] 运行中实例支持取消；失败节点支持重试；人工确认节点能等待并接受用户决策。
- [ ] 旧运行记录可兼容读取为历史工作流实例，不因结构升级丢失。
- [ ] 大型 DAG、长日志和频繁状态更新不造成整张画布反复重建或明显卡顿。
